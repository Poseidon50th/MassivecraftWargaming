# Upgrade an Existing v0.7.2 Site to v0.8.0

Use this shorter guide only when v0.7.2 multiplayer is already working.

## 1. Extract the safe upgrade

1. Extract `massivecraft-wars-v0.8.0-upgrade.zip`.
2. Confirm the extracted package does **not** contain `js/online/config.js`.
3. This omission is intentional. It protects the Worker address already stored in GitHub.

## 2. Upgrade Cloudflare first

1. Open the extracted `multiplayer-server` folder.
2. Click the File Explorer address bar.
3. Type `powershell` and press Enter.
4. Run:

```powershell
npm install
npm test
npx wrangler login
npm run deploy
```

5. Use the same Cloudflare account as v0.7.2.
6. Do not rename the Worker.
7. Do not delete either Durable Object.
8. The existing `workers.dev` address should remain the same.

## 3. Verify Cloudflare

Open the existing Worker address with `/api/health` added. Do not continue until it contains:

```text
"ok":true
"protocolVersion":3
"quotaHardened":true
"spectators":true
"customArmies":true
```

The upgraded server still accepts rooms created by cached v0.7.2 pages during the short update window.

## 4. Upload the website

1. Open `https://github.com/Poseidon50th/MassivecraftWargaming`.
2. Click **Add file → Upload files**.
3. Drag the **contents** of the extracted upgrade folder onto GitHub.
4. Do not drag the outer folder.
5. Confirm `js/online/config.js` is not listed as a replacement.
6. Commit with:

```text
Release v0.8.0 spectators, custom armies, and tactical AI
```

7. Wait for Actions and Pages to turn green.

## 5. Clear the old cached page

Open:

```text
https://poseidon50th.github.io/MassivecraftWargaming/?v=0.8.0
```

Press `Ctrl+F5` and confirm the header says `v0.8.0`.

## 6. Perform the three-window test

1. Create a room as host.
2. Open the opponent link in a private window and join.
3. Open the spectator link in a third independent window.
4. Click **Activate spectator mode**.
5. Propose and approve a battlefield.
6. Confirm both players privately choose armies.
7. Confirm the spectator sees readiness but not either private distribution.
8. Lock both armies and complete alternating deployment.
9. Commit host orders and verify the guest and spectator cannot see them.
10. Commit guest orders and verify all three windows show the same resolution.
11. Refresh all three windows and confirm they reconnect.

The full fresh-install instructions and troubleshooting are in `MULTIPLAYER_SETUP_GUIDE.md`.
